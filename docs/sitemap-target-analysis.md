Core source: `source/crates/core/src/sitemap_membership_analysis.rs`.
Core Store adds `sitemap_read_snapshot_with_membership_analysis(&SitemapMembershipAnalysisRequest)`; catalog, coverage, saved report, actual frontier counts and checkpoint are captured in one read transaction. Legacy `sitemap_read_snapshot()` retains its semantics and returns `membership_analysis: None`.

Existing GET `/api/crawls/{id}/sitemaps` adds optional query `page_limit` (0..200, default100) and independently typed `page_cursor`. Original raw `kind`, `limit`, `cursor`, source and membership filters are unchanged. Raw rows remain paginated by sequence. Saved requested-page findings are paginated by their actual ordinal in the immutable report. No long URL is encoded into the 4096-byte cursor. Both roles bind job/generation/config, catalog, full coverage and the stable saved-report context; page-varying facts do not enter that context hash. Raw CSV fields remain byte-for-byte original semantics; CSV reads only the same stable context and performs no target projection.

Inventory adds `membership_analysis: null | { context, location_findings, saved_pages, saved_pages_have_more, last_saved_page_url, last_saved_page_ordinal }` and `next_page_cursor: null | string`. Context engine is `open-seo-spider/sitemap-target-inlink-analysis-v1`.

Context fields: available, reason, generation, checkpoint_revision, outcome, report_sha256 (actual exact stored JSON bytes), report_bytes, saved_page_count, pending_page_count, source_scope and observation_scope. `website_wide_orphan_inference` is always false. Available scopes are completed_saved_report_observations, partial_terminal_saved_report_observations and mixed_age_selected_saved_report. Running crawls, missing terminal checkpoints, unavailable catalog and mismatching checkpoint context return unavailable with null findings, rather than an empty positive result. A report byte SHA mismatch, malformed required fields or input bounds fail atomically.

Each visible PageLocation finding binds sequence, observation_id, occurrence_id, entry_ordinal; original_membership_url, admitted_fetch_url and admission_decision remain separate. Original requested-URL observations retain requested_url, final_url, initial status, final_status, indexability and reasons, robots flag, error/truncation/renderer error, redirect presence, stored fetched_at, report ordinal and age_scope. An admitted rewrite alias has a separate observation and pending flag; it never supplies the original observation. A redirected final identity is never used for membership joining. States include redirected, non200, non_indexable, blocked_by_robots, fetch_failed, incomplete_observation, indexable, no_response, pending, no_stored_requested_observation and invalid_or_missing_original_location.

Each saved page reports original membership occurrence count, separate alias occurrence count, original membership classification, exact observed Anchor counts and up to five deterministic original source/requested-target/link-ordinal samples with text/rel/internal/nofollow retained. Counts distinguish self versus nonself, internal nonself and distinct nonself requested sources. Images/stylesheets never count as anchors. Negative classifications are permitted only by the existing captured source-coverage projection, scoped to valid normalized original PageLocs in current or historical declared sources. No source completeness means Unknown; historical negatives never become current positives. `listed_without_observed_nonself_inlinks` is a qualified report candidate, not a universal orphan assertion.

Additional source-document fields are `original_source_document_count` (DISTINCT requested XML task URLs), `original_source_observation_count`, `original_source_document_samples:[{observation_id,task_url,source_final_url}]` (one representative per distinct document, at most5), and `source_document_samples_have_more`. Repeated Locs in one document do not trigger the multiple-documents filter. Repeated observations of the same task URL remain one document; redirect-final source URLs never replace task identities.

Rendering facts are separate: rendered, raw rendered_url, safe normalized rendered_fetch_url (used only for comparing navigation), rendered_status, rendering_expected, rendering_state and rendered_navigation_changed. Fragment-only navigation preserves the raw fragment while retaining the same normalized fetch identity. Other browser navigation yields RenderedNavigationChanged, non200 browser response yields a qualified state, and missing expected rendering/status/usable URL does not become Indexable. No rendered identity participates in membership joining.

MCP spider_sitemaps retains its existing tool identity and25-tool inventory. It adds typed page_limit/page_cursor schema, exact pre-I/O role validation and GET query transport. Raw source/kind/membership filters apply to the raw-row dataset; independently paged saved-page findings cover all requested URLs in the selected report and the full captured source cohort.

Bounds: report bytes <=256MiB, report page count <=1,000,000, link records <=5,000,000, selected response rows/pages <=200 each; scalar/anchor strings are bounded and complete actual JSON still has existing8MiB atomic limit. The implementation hashes a borrowed SQLite report value and projects bounded scalar/anchor rows through SQLite JSON queries, with no full Rust Vec<PageRecord> allocation. Existing config64MiB bound, byte identity, SHA and provenance validation remain intact; config is now read as one exact bounded BLOB rather than repeated full-TEXT CAST/substr chunks.

It adds target filters and inspector facts plus an independent saved-page table/pager with explicit observed-inlink and historical/partial wording.
