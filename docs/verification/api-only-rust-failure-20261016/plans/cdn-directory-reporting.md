## Recommended own variant

Preserve the existing `CdnClassificationConfig` version1 and its serializer/validator/matcher exactly. Avoid silently widening its exact-origin strings or redefining configured_origin to contain a path. Introduce a **separate optional** `CrawlConfig.cdn_directory_reporting` with its own version1 object `{version:1, rules:[absolute directory URL strings]}`. None/null serializes absent and leaves legacy behavior/old saved bytes unchanged. The original declaration strings, including case and explicit ports, are retained exactly; only empty UI lines may be removed. This is a new own reporting profile, not the vendor's serialized schema.

Suggested first profile: max32 rules, max2048 UTF8 bytes each, explicit HTTP(S), ordinary ASCII DNS host including localhost, root or trailing-slash directory, no credentials/wildcards/query/fragment/backslash/control bytes. No user regex. A typed compiled rule holds lowercase DNS host with one leading www. removed, two literal host alternatives, optional explicit **non-default** port, and a literal case-sensitive directory prefix. Match either HTTP(S) scheme, exact host alternative, supported port condition and path.starts_with(prefix). `/assets/` excludes `/assets2/`; query/fragment do not broaden the prefix. Overlapping rules are OR; record all matching indices, never a winner/priority semantics. Duplicate compiled rules are refused.

Own normalization is explicitly revisioned: use existing credential-refusing normalize_url for candidates, never rewrite their stored original URL. No-port rules require normalized url.port()==None; an explicit non-default rule requires that exact numeric port on either scheme. **Reject explicit80/443 declarations in this first directory profile** rather than pretending lexical default-port equivalence is known; exact-origin version1 still supports them. Unicode/IDNA/IPv6 declarations, malformed escapes and dot-segment rule shapes are unsupported in this initial profile. Valid escaped path bytes remain literal (no percent-decoding or encoded-slash promotion); percent-hex case remains a deliberate literal distinction until independently specified. These are conservative own boundaries, not assertions that the vendor refuses those forms.

Store a distinct optional directory-report observation on PageRecord/LinkRecord: own engine/normalization revision, configuration SHA, bounded matching rule indices, selected original declaration for display, original seed-scope fact and grants_network_or_credentials:false. Existing version1 observation bytes/type remain unchanged. No retroactive classification of old saved reports. UI shows declared-rule provenance as plain text. A match may affect reporting's internal bool; scheduling must continue using original seed scope. Enabling either reporting profile activates the existing recomputation guard; do not duplicate or replace the crawler. No extra title/head/audit extraction is added without a concrete missing-field consumer trace.

## Small implementation boundary and controls

First Core slice: new typed config/compiled matcher/observation module plus tests; additive optional model fields; existing config validation; one composition seam at page completion and the existing seed-scope navigation guard call sites. Then connect the same model through existing API config_from_input/CLI --config/MCP inventory; extend capabilities truthfully. No JSON/version entry by users. Do not ship a disconnected configuration-only UI or claim a complete vertical slice until all consumers are connected.

Regression matrix: ordinary HTTP↔HTTPS; www in either declaration direction; nested/arbitrary subdomain and attacker-suffix negatives; root/assets/assets2; path case and literal metacharacters; supported8443 exact vs absent/mismatched port; explicit80/443 refusal in the new profile and unchanged acceptance in old v1; query/fragment candidates; percent-hex/encoded slash and Unicode/IPv6 unsupported-rule controls;32/33 rules and2048/+1 bytes; duplicates/overlaps/raw declarations; None/null/legacy roundtrip and no old-report backfill. A real finite A/B localhost+distinct-port fixture must assert exact GET ledgers, check_external false/true behavior, no HTML expansion from the declared external source, denied external redirect/resource/header/credential transitions, and durable cold config/report equality. API/CLI/MCP/UI save/reopen must exercise real consumers. Preserve existing12Rust/3Node assertions; derive new counts only from actual authored declarations.
