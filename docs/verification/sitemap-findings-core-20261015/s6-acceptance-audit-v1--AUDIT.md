## Required domains and three-valued selection

First five filters: **SavedPage**, exactly one candidate per actual original requested page in a validated terminal saved report, in original report ordinal order. An unfetched sitemap-only location is not a fabricated saved page. Its pending/unobserved target remains visible in the separate raw Location view. Source-only filters: **SourceAttempt/source evidence unit**, from real validated measurement records and explicitly unmeasured XML document/frontier evidence. Do not silently mix the two table domains or let a source-task URL become a page requested URL.

Use Match / NotMatched / Unknown as semantic outcomes; output selection of Unknown or All must retain reasons. Global unavailable report/history is an envelope condition, not an empty complete result and not a fabricated vector of unknown pages. Malformed/tampered SQL/config/hash/parent/receipt is an error, not an Unknown fallback. Missing historical capture, actual stopped measurement, omission and live report unavailability are honest evidence conditions.

The granular parameters `sitemap_sources`, `crawl_linked_sitemaps`, `max_documents` are capture/configuration context. Changing a query must not fetch, resume or invent sources. Exact requested/source selectors and search need one canonical meaning across adapters after Root agrees the actual interface. Limit/match-window selection is applied after the finding predicate, never after the first200 candidate rows.

## Non-indexable: recommended conservative local v1 decision

This resolves the old plan's open local policy for Root's implementation handshake, not vendor equivalence:

1. Require original membership for a positive row. A known not-listed page rules this conjunction out even if its target is unknown. A genuinely established indexable target rules it out even if membership is unknown.
2. A real robots **disallow** observation, native redirect witness, or native non200 response is a known local obstruction. Retain initial/final identity, status and reason. A later body/render problem does not erase an already observed native redirect/non200. Robots acquisition failure must be separated from an actual rule disallow.
3. For native200/direct identity, complete applicable document observation with actual known non-indexability reasons can match: scoped noindex/none, foreign canonical under existing local audit policy, or a known unsupported indexable-document type. A complete200/indexable observation is the negative control. False bool without a reason/basis is Unknown.
4. Body truncation, transport error/no response, required renderer absent/error/unobserved URL/status, incomplete PDF analysis or unknown historical qualification stays Unknown without the independent native obstruction above. Do not classify human reason text with substring heuristics or re-run a different robots parser.
5. Browser-only navigation or non200 remains **Unknown for original-target non-indexability in this conservative v1**, while retaining browser facts separately. A browser's final URL is not the original requested/native response identity. Root can deliberately adopt a wider browser-scoped policy later only with a versioned predicate and separate tests.

Actual evidence gaps in today's target projection are material: `crawler.rs:3674-3681` appends PDF-incomplete indexability false; `SitemapTargetObservation` lacks typed PDF status, so `page_from_row` may label it generic NonIndexable. `robots.rs:107-131` fails closed on unavailable robots, and `crawler.rs:3100-3102` sets blocked_by_robots plus robots_warning; the current projection loses warning. The new evaluator needs a narrow actual saved-page qualification for these facts (or a deliberately conservative Unknown), not a global reinterpretation of legacy TargetState or reason-string parsing. Explicit complete/disabled PDF versus partial/error/encrypted controls are required.

Conflicting directives use current `metadata.rs:454-509`: the saved configured bot governs scope; restrictive noindex beats index, none expands noindex/nofollow. A different bot's noindex is not applied. Duplicate self canonical is a control; the existing audit treats **any foreign canonical**, including self+foreign conflicts, as its local obstruction. This must be labelled local policy. Rendering re-extracts HTML directives, retains appropriate HTTP directives and preserves raw metadata; `renderer.rs:86-151` and `extract.rs:48-53` are the actual source basis. Tests must retain raw/rendered provenance and check same-URL rendered noindex versus raw noindex removed by observed rendered DOM, not merge both sources by hand.

## Complete stored selection, cursor and export gates

Use a real stored candidate cohort >400 saved pages and >200 source units; sole matches after200/400 must be returned or explicitly marked unscanned by a bounded-progress contract. Run page sizes1/10/200 over sparse matches and zero-match spans. Same-context complete traversal has exact independently expected identities/order, no duplicate/skip, and JSON union equals full export. A work limit must return explicit budget/error or truthful progressing incomplete scan, never complete0 from the first candidate batch. The current SQL page batch can remain bounded; the predicate must be evaluated before collecting output limit+1 matches.

Finding cursors need their own engine/version/domain and canonical filter+verdict+all exact selectors/search binding. Existing raw continuation, saved-page continuation and full raw-export tokens are incompatible roles. Malformed/wrong-role400; changed query/context409 before stale continuation selection can degrade into invalid-after; bounded input/output413. App job/config guards and SQL capture stay within the existing same-TX chain. CLI must not invent job UUID from the SQLite filename.

Actual source A revision, B association-only, fixed marker, historical None->Some, pending task, saved report exact bytes/checkpoint/generation/config, parent exact BLOB/presence and predicate version all invalidate bound finding cursors and exports. Same values pretty report bytes still change report context. Source findings must remain inspectable for a real live A-only capture even when saved-page analysis is unavailable. Corrupt tail/config/association must fail even if excluded by the filter.

Finding export needs a distinct schema/scope from the unchanged ten-column raw membership CSV. It evaluates exactly the same canonical selection/order in one verified read TX and uses bounded controlled transport/new-file output. Never export only loaded200 rows, silently omit Unknown, publish a partial prefix as success, or send a multi-MiB CSV through a bounded MCP JSON response by accident. Keep all legacy raw CSV/cursor fixtures intact. Website request count and DB/source bytes must remain unchanged for query/export.
