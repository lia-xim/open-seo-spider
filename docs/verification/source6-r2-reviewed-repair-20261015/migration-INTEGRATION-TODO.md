# http.migration — bounded Core proposal and remaining workflow

AUTHORED / NOT_COMPILED / NOT_RUN. The catalogue remains planned until a public workflow is implemented and actually verified. This proposal does not claim original vendor implementation or complete feature parity.

`evaluate_migration_csv(bytes, options, pages)` is a pure comparison over caller-supplied PageRecords. It returns website_requests=0 and explicitly says that it does not authenticate the caller's saved snapshot. A caller can supply synthetic records; the Core does not relabel these as performed network requests. No CSV upload starts a crawl.

The two selected columns use the existing strict list importer on the same bytes, twice, with the same delimiter/row/import limits. UTF-8 BOM, quoted commas/quotes/line breaks, blank records, missing columns, exact source positions, errors, original strings and URL normalization follow that importer. Default row1 is a header and comparison starts at row2; index/header selection and no-header start_row1 are explicit. The existing max_rows includes physical CSV records including the header. No new spreadsheet/XML parser or network provider is added.

HTTP comparison semantics are explicit: scheme/host/default port/dot-segment normalization follows normalize_url and URL2; query order, path case, trailing slash, scheme and existing escaped spelling remain distinct. Raw control characters, userinfo, relative and non-HTTP URLs are rejected. Input fragments remain provenance but are ignored for HTTP request lookup/final destination comparison. No anchor existence, browser navigation, canonical, content or redirect-permanence assertion follows. All 200..299 statuses qualify as successful final HTTP status; a matching404/304/500 does not pass. A final_url with absent final_status is a possible unfetched target and remains unobserved. Saved error/robots blocks, duplicate observations, invalid chain continuity/status/tail/loop and missing input fields have distinct outcomes. Duplicate mapping rows keep order and their first identical normalized pair; conflicting expected targets are annotated. The evaluator never chooses newest/first among duplicate observed requested URLs.

Resource contracts are independent: unchanged list import defaults8MiB input and each serialized import result, max50kCSVrecords/8192Bfield; supplied relevant observation text32MiB/count50k/hops32 per page; compact output8MiB. All are configurable only downward. Output rows are byte-counted before Vec retention, with a conservative1024B summary reserve and a final exact counting writer. A reduced output cap can refuse a report conservatively even when its final encoding might fit. This is no whole-process RSS or upstream saved-report allocation guarantee. Caller-owned PageRecord HTML/large unrelated fields are not cloned by this module.
