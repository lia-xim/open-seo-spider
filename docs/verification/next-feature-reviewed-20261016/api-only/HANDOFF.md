## Actual product flow

Core api_enrichment owns a version1 plan and typed report, retaining the existing ListImportResult with raw occurrence order, fragment/error/column metadata and input SHA. First-occurrence normalized URLs are executed once per job; duplicates still appear in every JSON/CSV input row. No CrawlConfig, CrawlReport or PageRecord is created. No crawler callback or outward-discovery path is called. Existing crawl/resource/scope/role/renderer logic is unchanged.

Production PageSpeedHttp always uses https://www.googleapis.com/pagespeedonline/v5/runPagespeed, HTTPS-only, no proxy and no redirects. URL, mobile/desktop strategy and performance category are typed. There is no runtime endpoint override, arbitrary script mapping or free provider JSON mapping. All mock transport implementations occur only in cfg(test) source modules. Their local HTTP API and separate website trap are real future test fixtures; no mock is a claimed real Google result.

The application makes provider API requests, not supplied-site crawl requests. Google may itself fetch the submitted site. The preview and standalone UI disclose this distinction and start requires explicit acknowledgement. API HTTP status is labelled separately from website status; remote requested/final URLs remain provider observations. Missing Lighthouse or metrics are unavailable/None, never a zero or a PageRecord fact. Response bodies are not saved as untyped data; only bounded typed metrics, body byte length and SHA survive.

The common App Service is used by HTTP, explicit CLI and MCP through the same HTTP service. It has a retained TaskOwner (api_enrichment_operations), max4 concurrent jobs, max1000 store entries and one sequential provider operation per job. Lifecycle installs this service once; legacy unit-state constructors can retain an empty slot. EOF closes shared admission, cancels every active operation and awaits its actual owner drain along with all pre-existing drains, even when another drain fails. The legacy three-owner receipt remains unchanged; an additional api_enrichment_operations object reports this new owner. This is not a claim about outside process or pipe closure.

## Authority and persistence

The service opens without creating any new store directory on ordinary App startup. Only an explicit admitted job lazily creates its store; each new UUID directory exclusively creates input.bin, plan.json, then report.json and completion.json with fsync. Original input bytes/hash are checked against a freshly derived import plan before any provider call. Completed report reads bind exact bytes/SHA, plan SHA, job ID and generation1. Public readers cannot upload report observations. The immutable completed snapshot has generation/filter/job-bound cursors, max200 rows and full occurrence CSV. Changed snapshots, plans, config inputs, cursors or filters refuse. Reopening uses only local files and makes no provider request. Running crash remnants become interrupted; there is no automatic provider resume. A new explicit execution produces a new job ID, not an in-place report rewrite.

The standalone /api-enrichment page previews UTF-8 TXT/CSV/XML, explicitly starts/cancels, paginates, downloads full CSV and reopens input/configuration/results by job ID. It preserves an advanced saved CSV selector/budgets while allowing strategy/profile edits. It saves only the last job ID in browser localStorage. It renders observed data with textContent. There has been no actual browser1440/320 proof yet. Binary XLSX is supported only through the explicit local CLI importer; its report can be reopened, while binary input cannot be edited in the UTF-8 web form. Job listing/deletion/automatic resumption, account OAuth/vault/rotation, CrUX and five other reference providers are explicitly outside this V1.

Credential profiles are anonymous or page_speed_environment. Only an actual explicitly started environment-profile operation reads OPEN_SEO_PAGESPEED_API_KEY at runtime. HTTP/MCP/UI/CLI options never contain a key value or free endpoint. Key bytes are borrowed into the fixed adapter request, not a serializable/debuggable request DTO or saved option. Reqwest error objects and raw provider error bodies are not surfaced or persisted; typed generic failures are used. This is a foundation, not a secure memory-zeroization or OS-vault claim. Supplied input itself is retained as user-provided material; users must not paste secrets into that material.

## Bounds and outcomes

Input<=8MiB /existing importer rows<=50000; URL<=8192 bytes; calls1..100000; retries0..2; response1..32MiB; request timeout100..120000ms; whole-job monotonic deadline100..3600000ms (default15min).429/retry-after<=30s and transient failures retry only within both deadline and attempt budget. provider_request_attempts counts calls admitted to transport.execute, including an attempt cancelled before reaching the wire; it is not an invented successful network-send count. Per-observation JSON<=65536 bytes and aggregate logical observation JSON<=32MiB; full plan/report/config<=64MiB; row JSON<=8MiB; full CSV<=64MiB; MCP body<=1MiB with explicit refusal to use smaller pages/CLI. These are logical byte caps, not a whole-process RSS guarantee. Wire start input is capped64MiB so escaped8MiB UTF-8 input is representable; small read requests are capped8192 bytes. No global cache or cross-request authority session exists; each report page verifies/parses the full local bounded report again, which is an explicit current performance boundary.

Cancellation closes/drops the current transport future, stops later URL attempts and retains a cancelled/partial report when persistence succeeds. Real process EOF joins must still be independently exercised by Root. Partial provider outcomes are explicit in the saved report; CLI exit success means a valid bounded job/report/export was produced, not that every provider observation succeeded. New failed output files may remain empty; no input/existing output is overwritten or deleted.
