# crawl.limits — bounded next-batch plan

Basis: immutable Source10 manifest12b238c43bd504b71e4948a8e11d4622f34589a35290ca8ef923b833464206c7, code c6bd9c50a0dfcfb434a7747a2052aab961d00ef7,369 inputs. Source-only analysis; no implementation, compiler, fixture, browser, HTTP target, SQLite execution, Git or Root mutation. This plan does not claim Source10 fullsuite/build/native acceptance or manufacturer parity. Exact source pins and bounded line regions are in evidence.json.

The catalog marks crawl.limits partial/P1. Its missing controls are admission limits rather than replacements for retained observation budgets. The current official [configuration guide](https://www.screamingfrog.co.uk/seo-spider/user-guide/configuration/#limits) separately describes per-depth URL counts, folder depth, query-string counts, per-subdomain totals, URL length and hyperlinks crawled per page. Folder examples distinguish directory-ending path segments from a final file-like segment. It also lists per-path quotas. Documentation does not settle every Unicode/counting/redirect/concurrency detail below; those are explicit proposed product semantics, not proven vendor equivalence.

## Existing mechanisms and exact seams

- Core models.rs:6–67 contains optional max_pages/max_depth, concurrency, body/redirect controls, include_subdomains and separate policy/resource/source budgets. Crawler::new at crawler.rs:126–160 rejects invalid execution settings but maps legacy Some(0) page/depth to None. Preserve that legacy contract.
- crawler.rs:613–671 checks the legacy normal-run cap using completed transports (or retained pages) plus in-flight tasks before dispatch. Selected recrawl instead has its own admitted_this_run/max_attempts. This is URL-task admission accounting, not a bound on every website HTTP request or retained occurrence.
- Legacy page-link expansion at crawler.rs:685–711 checks page depth then iterates retained PageRecord.links and deduplicates through seen before adding the next frontier entries. Policy rows at1353–1385 keep observations and label selected_no_expansion/depth_limit/source_incomplete rather than fabricating a fetch. Resource permission at1144–1200 independently records grant/no-grant and complete source facts.
- store.rs:2020–2067 commits resource observations/transport and then INSERT OR IGNORE frontier rows in one transaction. Preserve this complete-source/permission/history authority; source-only counter changes must not overwrite original resource grants or upgrade old observations.
- extract.rs:140–182 retains every parsed anchor occurrence, including duplicate destinations. onpage.rs:273–299 counts those repeated anchors for high-outlink audit notices; onpage.rs:424–436 emits url_long from Unicode character count. Those AuditThresholds are not fetch guards.
- ResourceDiscoveryLimits at resource_policy.rs:191–215 and LiveCrawlPolicyLimits at policy_ledger.rs:15–59 are bounded source/row/batch work and retention controls. resource_capture.rs:170–210 marks incomplete/error or refuses candidate overflow. Do not relabel their captured prefixes as complete or reuse those hard memory caps as a configurable number of followed links.

## Minimal coherent opt-in batch

Add one versioned strict optional crawl_admission_limits object, None preserving all existing behavior. Keep it separate from AuditThresholds, CrawlPolicyLimits, ResourceDiscoveryLimits and operational speed overrides. New fields use explicit units and no undocumented zero-to-unlimited coercion; absence means disabled, zero is meaningful only where the documented field permits no candidates. Validate the entire object before store/bootstrap or website IO. Suggested six controls:

| Control | Proposed exact scope and identity |
|---|---|
| URLs per crawl depth | Unique PageDocument frontier fetch identities admitted at their recorded depth, including configured seeds at depth0. Duplicate occurrences do not consume extra quota. |
| Maximum folder depth | Normalized URL path's literal completed slash-delimited segments; root0, /a0, /a/1, /a/b1. Encoded %2F is not a separator; duplicate literal slashes must have an explicit tested rule, preferably count them rather than create a bypass. |
| Maximum query tokens | Per-URL raw query tokens split on literal ampersand, preserving duplicate keys and empty tokens under a documented rule; no sorting, parameter rewriting or conflation with policy.max_query_tokens (a work ceiling). Zero can mean no query tokens. |
| URLs per host/subdomain | Exact normalized IDNA/IPv6 hostname bucket; declare whether ports/schemes share a bucket (proposed yes). include_subdomains remains an eligibility switch, not a numeric quota. |
| Maximum fetch URL UTF8 bytes | Length of normalized effective fetch alias, with observed original URL unchanged. Explicit byte label; audit max_url_chars continues to count characters for notices. |
| Navigation targets per source | First N eligible unique hyperlink fetch targets in a defined stable source order; resource/CSS candidates are not silently included. Preserve all retained occurrences, duplicates, source positions and audit totals, with separate followed/denied counts and reason. |

Use one pure shape/decision module for normal seeds, legacy page discoveries, native policy aliases, and resource-ledger frontier tasks. Check static URL shape after normalization/policy aliasing and before any fetch, and again on a redirect target before following; never rewrite observed identities. Per-depth/per-host limits count a unique admitted original frontier task once, while redirect hop limits remain max_redirects. A different policy that counts redirect hops as separate quota URLs needs an explicit later design/test contract.

Dynamic quota reservations must be durable and atomic with frontier admission, not independent check-then-spawn counters in concurrent futures. Introduce a generation/config-bound admission ledger with accepted/denied reason, identity, depth/host keys and one reservation per task. Resume must reconstruct or verify reservations from authoritative durable state; failed fetches remain attempts, retries/resume must not double-charge an existing reservation. Keep pending candidates when a quota is exhausted and report the limiting reason; do not mark them fetched, truncate a saved count, or silently discard their source evidence. Reservation rollback and crash-before-dispatch semantics require explicit tests before choosing a concrete table/state design.

For an already-created resource grant, a later dispatch quota denial is a separate admission observation, not retroactive mutation to no_grant. For memory-only crawling use the same decisions and counters, with explicit non-durable scope. Bound the new denial/reservation ledger independently and fail before partial commit if its own retention ceiling is exceeded. Selected recrawl has different existing max_attempts/no-expansion semantics: integrate it explicitly in the batch or refuse unsupported opt-in combinations before IO; never silently bypass configured limits.

## Channels and acceptance

App config adapter server.rs:851–870, start/resume paths:1215–1286, CLI main.rs:250–258/724–771, MCP schema mcp.rs:535/552 and UI app.js:383/1288–1305 all need saved roundtrip/strict validation. New admission fields must not become unvalidated flattened UI values or an implicit resume speed override. Show denied reason/used/reserved counters and distinguish observed links, eligible targets, admitted requests and stored pages.

Do not claim browser subrequest control from a native frontier cap: renderer/server.mjs has separate4-context/64-queue, event and HTML budgets, and browser navigation/subresources need their own request-interception contract. Rendered DOM discoveries can feed the same later frontier decision, but that does not limit requests already made by Chrome. Sitemap protocol/source/archive, robots fetches, PDF workers, downloads, MCP wire limits and read/export ownership remain separate. Existing 64MiB source,8MiB JSON and64MiB CSV/read-only authority are not widened.

Recommended focused source tests: exact-minus/equal/plus for all six fields; Unicode/percent encoding/query duplicate/empty tokens/IPv6/ports; alias-vs-observed identity; duplicate DOM occurrences retained while unique fetch count is limited; mixed source channels and multiple seeds; concurrent last-slot admission; memory vs actual SQLite parity; cancellation/crash/reopen and failed-attempt reservation; selected-recrawl refusal/explicit semantics; source over-budget rollback preserves old complete ledger and counts. None/default fixtures must remain byte/behavior compatible.

Recommended later genuine native acceptance: own finite website with2depths,2hostnames,folder/query/encoded-URL neighbors and repeated anchors; held responses force concurrent last-slot contention. Exact per-path GET log proves no denied target is requested, with robots and redirect requests itemized separately. Assert every original occurrence and denied reason in saved report/verified ledger/CSV, cold resume without quota reset, and UI/API/CLI/MCP save/reopen equivalence. Separate actual Chromium fixture is required before claiming renderer network parity. No such test was executed for this plan.
