# Named table views

[Bounded native acceptance](verification/table-named-views-20261019-r3/README.md) passed on the exact reviewed normal executable and frozen source. All 43 registered UI suites passed together in a fresh complete R3 retry. The earlier R3 whole invocation remains FAIL after 11 successful suites and a dom-capture Node process exit 3221226505 (0xc0000409), without stderr or timeout; a separate unchanged diagnostic passed. The crash cause remains NOT_PROVEN. The earlier [table-filter acceptance](verification/table-explorer-20261018-r4/README.md) applies to its own source revision. Public CI for this new source, broader table/browser scope and manufacturer parity remain open.

Open **Ansicht und Filter → Benannte Ansichten** in a main result table. A named definition contains the section filter, search text, active AND rules, sort column/direction and ordered visible columns. **Als neue Ansicht speichern** saves a definition; selecting a name does not apply it. **Anwenden** explicitly installs the complete query on the currently selected crawl and starts at its first results page. Page size and inspector state are separate controls.

Definitions can be applied to another crawl in the same section when the complete column/type/identity and section-filter contracts match. A maintained query-semantics version also guards changes to raw measurements and existing filter meanings. Incompatible definitions remain visible and refuse application. There is no automatic migration or partial application.

**Umbenennen** changes the selected definition's name. **Mit aktueller Ansicht überschreiben** replaces its query while keeping its existing name. Delete has a separate confirmation. Names are unique within a section after NFC normalization, trimming and German lowercase comparison; accents and internal spaces remain distinct. Display spelling is retained. Saving over the currently applied definition clears its unsaved badge; renaming that same definition updates the badge name while preserving any unsaved query state. Deleting it removes the badge while leaving the working query unchanged. Selecting or editing another definition does not switch the active view.

The catalog belongs to this browser origin, including its port. It contains definitions, not rows, native project IDs, snapshot tokens or crawl generations. Search text itself may contain private information. There is no server upload. The earlier per-crawl column-only preference keys remain separate. Applying, renaming or deleting a named definition does not silently save those legacy preferences.

Mutations use one cooperative Web Lock and compare the exact previously read catalog bytes. Busy, unavailable, stale, corrupt and quota-limited storage produces a visible refusal. There is no retry, replay or automatic overwrite. Other tabs' changes preserve the working query and old visible entry list but disable Apply and catalog mutations until explicit reload. Browsers without Web Locks can read and apply compatible definitions but cannot change the catalog through these controls. This serializes cooperating tabs; it is not a universal cross-process transaction against arbitrary scripts.

**Alle einfachen Ansichten entfernen** requires a second confirmation and removes the v1 catalog key across all sections. The separate [grouped-view catalog](table-query-expressions.md), current query, saved native reports and legacy column preferences remain. This is also the explicit recovery path for corrupt, unsupported or oversized catalog bytes. A changed owner, query, mode, selection, name or catalog invalidates an earlier confirmation or pending operation. Without a selected crawl, catalog read, rename, delete and reset remain available in the selected query mode; creating, replacing or applying a complete query requires a current crawl.

Configuration bounds are 32 definitions in the whole catalog, 128 UTF-8 bytes per name, 512 KiB per definition and 2 MiB per catalog. Existing query/schema bounds also apply. These bounds do not cap crawled URLs. Larger catalogs, portable definition import/export, native preference persistence and broader browser compatibility remain separate work.

The native receipt covers five groups, two separately captured 107-page crawls, 29 complete title-table observations, nine actual CSV downloads with 719 data rows and 26 desktop/320 px geometry observations. Every selected table and complete ordered CSV/provenance cell is checked independently against native facts. Apply itself resets a later results page before the row oracle runs. Same-ID badge changes, CRUD, real Web Lock contention, same-tab exact-byte CAS, a separate genuine cross-tab storage event, actual Chromium quota, corrupt-byte reset and immediate search/owner races are exercised. Two native processes close naturally with EOF/exit 0. A fresh same-origin browser context restores the catalog without auto-Apply; original saved reports and cold CSV bytes remain unchanged under two positive HTTP-410 controls and zero website refetches.

The missing-Web-Locks control uses a real insecure owned read-only HTTP passthrough to the unchanged native loopback service. The native direct alias-host request remains separately refused with HTTP 403; the fixture does not add supported alias binding. Unsupported/oversized catalog recovery, incompatible schema/query semantics, no-crawl gating and additional name/selection/contract races have separate pure controls; they are not all native browser scenarios in this slice. Other sections/operators, portable/native named preferences, OR/nested queries, XLSX, specialist cursor/export contracts, other browsers and large-corpus/resource limits remain open. The installed Source16 pilot is unchanged. Pure tests and this bounded native corpus do not establish full manufacturer parity.
