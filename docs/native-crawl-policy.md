# Native crawl policy and admission evidence

The native HTTP crawler can apply an explicit `CrawlConfig.crawl_policy`. The independent policy engine evaluates exact origins and folder/exact-path scopes, optional query-key removal and ordering, ordered Rust-regex rewrites, and include/exclude decisions. Its deterministic offline preview performs no website requests. Native execution requires a SQLite store and rejects policy combined with browser rendering or the older top-level include/exclude patterns before any website request.

Observed source URLs are kept separately from operator-created fetch aliases. A link `href`, PDF URI action, sitemap `<loc>`, declared input or actual redirect `Location` remains evidence of what was observed. Query transforms and rewrites can choose another fetch URL; they do not rewrite the saved link graph, canonical declarations or observed fragments. Relative references use the observed document/base address. Legacy records without a raw attribute are explicitly identified as resolved fallbacks.

An allowed fetch task stores an immutable `PolicyAdmission`: policy SHA, originating occurrence, actual fetch URL, task role and independent page/XML discovery permissions. The first admitted task for a URL and role wins. Later occurrences coalesce into that task without upgrading its permission. An outside-scope check can fetch a response but cannot expand its page links; a sitemap task has a separate XML-discovery permission. Actual redirects are evaluated without query transforms or rewrite rules before the target request. A denied redirect keeps its observed location and never fetches that target.

Custom HTTP headers retain the original configured seed-origin grants. Rewritten seeds, extra scope roots, selected recrawl targets, robots requests and protocol-discovery origins do not grant new credential origins. Robots decisions apply to the actual fetch target. Browser rendering with live policy is currently unsupported; native policy does not claim to control JavaScript navigation or subresources.

Every declared list occurrence is retained in admission evidence, including duplicates and rejected rows. A rejected importer row stays rejected even if its raw formula cache contains a valid HTTP URL. PDF URI actions retain their raw URI and rejected protocols. Incomplete PDF annotation extraction cannot establish complete candidate coverage. Sitemap roles preserve invalid and duplicate parser-observed locations; a failed or denied sitemap redirect still retains observed redirect decisions.

The source page/protocol result, its new task frontier and its policy occurrences commit together in one generation-guarded SQLite transaction. A failed write or an explicit policy storage limit rolls back the entire source commit. The source stays pending; children cannot escape a failed commit. Pause stops new admission and drains started work. Cancel or process loss can repeat an uncommitted request on recovery; committed occurrences and saved fetch identities are reused without applying rewrites a second time.

`live_policy_limits` is optional. Defaults bound an individual occurrence to 262,144 serialized bytes, a source batch to 33,554,432 bytes and 100,000 occurrences, and a read page to 1,048,576 bytes. `max_ledger_bytes: null` leaves total ledger size unrestricted; there is no 500-URL or total-record limit. Bounds fail explicitly rather than discarding observations or claiming completion. Limits control serialized evidence, not the already-observed response body, whose existing HTTP/PDF limits still apply.

`CrawlStore.policy_occurrences(after_sequence, limit)` reads 1–1,000 rows per page. Byte shortening can return fewer rows while preserving the sequence cursor and `has_more`. `visit_policy_occurrences` holds one read transaction, verifies the saved policy/admissions once before emitting data, and visits bounded pages from that same snapshot. A concurrent writer may append another generation; a streaming export retains its original rows and summary. A disconnected consumer aborts the reader. Separate read-only handles avoid reentering a store mutex. Legacy stores emit one empty page without migration.

`PolicyLedgerSummary.complete` describes observation coverage, not just export success. Pending tasks, failed/truncated sources, incomplete policy evaluation or unavailable inherited history keep it false. A snapshot export can include every saved row while the ledger remains incomplete. A policy-denied redirect without a final document body is one such incomplete source. A selected recrawl retains its exact parent snapshot and saved permissions; its child ledger exposes current observations and a separate `inherited_history`. Missing parent ledger rows remain unavailable. Unknown parent hash/count are `null`, never an inferred zero or complete history.

Recovery checks the effective policy SHA, rolling serialized occurrence digest and byte count, SQL/JSON occurrence identity and generation, source completeness count, and each frontier admission's exact originating decision. Inherited permissions must match the immutable selected parent target. These are controlled-writer consistency checks, not an external signature or proof against an attacker able to rewrite every related database artifact coherently. Optional absent policy fields are omitted from config, page, report and checkpoint serialization so pre-policy hashes remain compatible.

Directed acceptance fixtures cover rewritten alias coalescing, preserved fragments, origin/folder scope, credential isolation, actual-path robots, sitemap roles and failed redirects, importer rejects, pause/crash recovery, selected children, atomic write failures, explicit limits, tampering, snapshot streaming and more than 500 native pages. They establish this independent contract; universal behavioral parity with another product is not established.
