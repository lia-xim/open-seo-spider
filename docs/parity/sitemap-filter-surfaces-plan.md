## One query kernel, two explicit result domains

Add a Core sitemap_findings module, leaving the original raw ledger API/CSV intact. A typed Filter enum carries the seven existing granular IDs; its domain is fixed (first five SavedPage, last two SourceAttempt). An additional assessment selector Match/Unknown/All exposes uncertainty; it must not turn Unknown into NotMatched. A bounded exact requested-URL/source-task selector can be added once to the canonical query, shared across all adapters. Do not accept discovery max_documents/crawl_linked_sitemaps as result filters: these are saved capture settings whose actual effective values belong in provenance, not instructions to fetch additional sources.

Proposed handshake names, to agree before implementation:

- SitemapFindingFilter; SitemapFindingSelection (filter, assessment, optional exact requested/source identity, bounded search, limit1..200).
- SitemapFindingVerdict = Match / NotMatched / Unknown; each row has typed reasons and the actual evidence scope.
- SitemapFindingRow = SavedPage(existing SitemapSavedPageFinding plus filter assessment) / SourceAttempt(new compact public projection). Domain mismatch is rejected before Store I/O.
- SitemapFindingsContext: engine/schema, actual generation/config, catalog state, source measurement context, bound report/checkpoint context when required, inherited parent basis and saved capture limits, plus unavailable/omission reasons. Do not invent complete-cohort totals from sidecar record_count.
- CrawlStore::sitemap_findings(selection, after) and write_sitemap_findings(selection, expected_context, writer) share one private traversal/evaluator and the existing verified same-TX loaders. Public writers return no successful prefix on failure. Writer is a new bounded export, not a source-record mutation.

Store owns transaction lifetime. Reuse store.rs load_sitemap_read_snapshot_verified2338 and v2 exact-parent source loader2477-2512, not a report-only bag. Source findings can remain available for a real A-only capture before terminal report publication. SavedPage findings retain all current terminal report/checkpoint/source equality gates (membership_analysis403-486); unavailable target analysis returns explicit unavailable, not an empty successful selection. Current generation/config, report and source contexts must be from this same read transaction. None remains historical unknown; no migration or recrawl is triggered by reading.

Do not obtain full selection by filtering the first200 output rows or by a browser loop that silently loads every page. Factor the current private analysis traversal so full stored candidates are examined in stable original page ordinal order in bounded chunks, using its exact original identity/source/inlink joins. Apply the predicate before selecting limit+1 matches. Core analysis523-525 currently limits page candidates before external UI predicates; wrapping that one page is insufficient. Report/page/link/catalog bounds remain enforced. If any work/input/export budget prevents a full decision, return an explicit budget error or truthful incomplete scan with a progressing cursor; never has_more=false/full_count=0 merely because the candidate window ran out. Total matched count is optional until exhaustive evaluation is actually completed.

This is a bounded all-stored selection, not an unlimited export/scalability claim. A full export traverses the same predicate/order in one read transaction and bounded writer; overflow fails atomically (existing8MiB page/32MiB raw CSV policies are not silently raised). CLI writes a new destination only, via existing guarded export patterns. S4 streaming membership/paging remains separate and open.

SourceAttempt output needs: actual measurement_id/sequence, original requested task URL, requested/final transport identities, capture generation/config and initial-catalog anchor separately, document kind/namespace/profile, transport received-versus-retained quantities, decoded bytes+precision/hash extent, scan counters+precision, both threshold verdict/basis/proof_quantity, integrity/status/stops and effective capture limits.

Call the existing pure projector (measurement.rs828-868/871-998), not duplicate its logic. Preserve expected_source_observation_id as expected identity only. A separate membership association view joins the validated B association by measurement_id and exact committed document receipt. State must distinguish observation_only, committed document (actual retained_rows_complete qualifies it), legacy document without measurement, pending task and unknown capture. Capture membership_retention=Complete describes captured legacy parser rows before B; it never proves SQL membership retention. An A-only count excess must stay selectable even with no committed Document.

Enumerate stored measurement attempts plus genuinely unmeasured legacy XML documents/pending XML tasks using verified actual identities; robots.txt declaration documents are not XML source-limit rows. Do not create one fake measurement per missing task or assign the fixed global omission marker to a particular task without evidence. Envelope-level legacy_history_unknown, CaptureUnavailable/StorageBudgetExceeded marker, and inherited context qualify any enumerated cohort. Known zero and Unavailable remain separate. No new durable S3 schema/payload rewrite is needed for this projection.
