# Reference runtime and acceptance boundaries

The installed Screaming Frog SEO Spider24.3 normal Windows CLI is usable for the controlled local reference crawl under the current missing-licence state. This is observed execution, rather than a blanket entitlement claim. No licence file was read, installed, modified or bypassed. The vendor documents a separate Windows CLI executable and ordinary crawl/export arguments in its [official CLI guide](https://www.screamingfrog.co.uk/seo-spider/user-guide/general/).

`scripts/reference-membership.mjs` runs 78 selected named filters plus nine `All` cohorts in one ordinary invocation against original independently authored localhost HTML. The fixture stays below100 distinct paths. Results are normalized by exact filter argument and path in `reference-membership/latest-run.json`; the original CSV and completion/request records remain bound to that run. A filter with zero rows is an observed empty set, not successful acceptance or evidence the rule does not exist.

The original CLI writes its ordinary profile during shutdown. Before/after byte snapshots remain only in task-local `work/reference-membership-profile`; repository artifacts contain hashes and changed-key classifications. The measured run has no changed property values or keys. The runner does not write configuration, control the existing GUI, roll back unknown state, supply credentials or change licensing.

The 64 initial trigger/control pairs and four explicitly refined control pairs are scoped reference observations. The original baseline has multiple query/redirect aliases with identical metadata, and its title exceeds the current60-character preference. That makes it an unsuitable duplicate/length negative control; these contradictions remain recorded rather than removed.

Ten selected filter probes remain partial:

- `H2:Non-Sequential`: the authored H2-before-H1 fixture confirms the H1-order condition but does not isolate the documented H2 condition. A separate H1→H3→H2 fixture is needed; the [official H2 description](https://www.screamingfrog.co.uk/seo-spider/user-guide/tabs/) distinguishes the second heading level after H1.
- `Links:Internal Nofollow Inlinks Only`: its target is not in the `Links:All` cohort, so there is no valid negative-membership inference. The vendor documents that following internal/external nofollow, sponsored, ugc and page nofollow is [disabled by default](https://www.screamingfrog.co.uk/seo-spider/user-guide/configuration/).
- `Links:Pages With Uncrawlable Internal Outlinks`: a span href and click handler are present, but the filter is empty. Storing/crawling these formats is [disabled by default](https://www.screamingfrog.co.uk/seo-spider/user-guide/configuration/), so this is an eligibility/configuration question.
- `Canonicals:Unlinked`, `URL:Broken Bookmark`, `Links:Follow & Nofollow Internal Inlinks To Page`, `Links:Pages With High Crawl Depth`, `Links:Non-Indexable Page Inlinks Only`, and internal redirect chain/loop exports are empty despite the intended authored cases. Their prerequisites remain to be calibrated. The vendor documents that some filters require [post-crawl analysis](https://www.screamingfrog.co.uk/seo-spider/user-guide/configuration/), with manual start or automatic analysis enabled in configuration. Empty output cannot establish whether that prerequisite was fulfilled.

Installed CLI help exposes no dedicated `--crawl-analysis` switch. Configuration import is a separate advertised operation; this probe supplied no config/auth flag and did not alter preferences. No exact licence blocker for these partial filter cases has been measured. Paid rendering, advanced configuration, authenticated providers and behaviour beyond500 URLs are **NOT PROVEN** in the original reference runtime.

`scripts/reference-parity.mjs --reuse-reference` runs the independent engine against the identical retained baseline fixture definition and verifies its SHA-256 before comparing stored reference CSVs. `SPIDER_BINARY` selects the executable; output binds the result to its SHA-256. Origin, volatile timestamps and localized labels are normalized explicitly. Initial-response and final-document data remain visible. Anchor metrics are compared with anchors; total non-anchor references stay separate. Pixel measurements are actual recorded values, with remaining font/kerning/rounding differences retained.

The 416 named-filter backlog, 32 additional workflow contracts and 93 independently authored accessibility fixture pairs are acceptance/tracking detail. Related grouped capability evidence does not confer per-filter implementation status. Independent pinned axe execution distinguishes automated violations from incomplete/manual review and does not prove the original engine's rule mapping. **Full product parity remains NOT PROVEN.**
