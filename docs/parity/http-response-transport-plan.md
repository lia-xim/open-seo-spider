# Locked inbound HTTP inventory and concrete integration

DESIGN_ONLY_NOT_IMPLEMENTED_NOT_RUN. This is a narrow supplement to http-response-body-drain-design-v1, not a Source5 or Source6 runtime result. The Root decision carried into this proposal is a five-second inbound HTTP grace period, followed by cancellation of the remaining owned inbound transports. Outbound crawls and actual verified-worker joins remain awaited without a universal five-second completion claim.

## Actual locked feature boundary

The inspected frozen Source5 workspace has only Core and App members. App depends on Axum0.8 with defaults and Reqwest0.12 with default-features=false; Core also disables Reqwest defaults. Axum's locked0.8.9 defaults select http1, form, json, matched-path, original-uri, query, tokio, tower-log and tracing. They do not select http2 or ws. The explicitly selected Reqwest TLS/compression/JSON/stream features do not add http2. The actual lock resolves Hyper1.12.0, hyper-util0.1.21, Reqwest0.12.28 and has no h2 or tokio-tungstenite package. Hyper's http2 feature requires h2; this locked graph therefore does not establish HTTP/2 support.

Cached release fingerprints independently list Axum http1/nohttp2/nows, Hyper client+http1+server/nohttp2 and hyper-util http1/server/service/tokio without http2. These are corroborating pre-existing build metadata only: they are not bound proof of a future Source5 R2/Source6 executable. No compiler or cargo feature command was run for this inventory. The eventual actual build admission must check its own enabled-feature evidence and retain this protocol scope.

The current listener is plain Tokio TCP, not a TLS acceptor. Inbound TLS/ALPN and QUIC/HTTP3 are not provided by this serve path; the mere presence of TLS/QUIC client dependencies in Cargo.lock does not create an inbound protocol. Outbound crawler/MCP Reqwest clients remain separate.

Avoid a subtle feature expansion: hyper-util's convenience feature `server-auto` enables both http1 and http2, and `full` does the same. The `server::conn::auto` module itself is available with server plus either http1 or http2; it does not require `server-auto`. The narrow proposed direct dependency is the already locked hyper-util=0.1.21 with default-features=false and features `["server","http1","service","tokio"]`. Its existing client features remain unified through Reqwest; no new package/version or protocol is requested. This suffices for TokioIo/TokioExecutor, TowerToHyperService and the same auto connection builder currently used inside Axum. No new direct Tower or Hyper dependency is needed if these public adapters infer request/body types. Actual compilation must validate that choice before admission.

## Inbound routes and upgrade inventory

Production server.rs builds one Router with GET/POST MethodRouters plus the merged sitemap-findings routes. It retains DefaultBodyLimit64MiB, the comparison-specific request limit, lifecycle request middleware and outer local-origin middleware. The host must be a loopback authority, and a present Origin must match it. The listener address is registered with the MCP bridge before serving. Startup recovery, URL printing and ready notification currently precede serving; retain that order. No custom fallback, route_service, nested external service or application ConnectInfo dependency was found in this route construction.

No application WebSocketUpgrade, on_upgrade, hyper::upgrade, CONNECT MethodRouter, custom switching-protocol response or tunnel handler was found. `/mcp` is a JSON POST dispatch endpoint, not a WebSocket/HTTP2 tunnel or stateful SSE server. Existing Axum internally uses `serve_connection_with_upgrades` generically, but no current handler consumes an upgraded IO. Ordinary CONNECT to existing paths follows the router's method handling; authority-form/unknown paths follow current routing/parser handling. Preserve the existing actual status behavior in before/after tests rather than inventing a new proxy/tunnel API or promising one universal CONNECT status without executing the real requests.

Reuse the same upgrade-capable builder for compatibility, but document that the ownership contract covers the current non-upgrading application. A future handler which obtains Upgraded IO could transfer that IO beyond the connection future and would need a separately retained upgrade owner before it can be added. Add a source/acceptance guard against introducing a successful101 or2xx CONNECT tunnel without that review. No new WebSocket, CONNECT, HTTP/2 or HTTP/3 capability is authorized.

## HTTP/1.0 decision: narrow pre-worker refusal

Select the small explicit refusal rather than spooling policy/resource exports merely to calculate their length. The four affected paths are:

| Path | Handler |
| --- | --- |
| `/api/crawls/{id}/policy.json` | policy::export_json |
| `/api/crawls/{id}/policy.csv` | policy::export_csv |
| `/api/crawls/{id}/resources.json` | resources::export_json |
| `/api/crawls/{id}/resources.csv` | resources::export_csv |

For HTTP/1.0 GET and automatic HEAD on exactly these MethodRouters, return505 HTTP_VERSION_NOT_SUPPORTED before job lookup, SQLite availability checks, response permit acquisition or producer registration. Use the existing `{ "error": ... }` ApiError shape with a fixed message explaining that this streamed download requires HTTP/1.1, a bounded in-memory error Body with known length, and Connection:close. A route-local middleware can read `request.version()` without changing each public handler signature; keep it inside the unchanged global local-origin and lifecycle layers. Existing global host/origin rejection still takes precedence. Preserve normal wrong-method/path handling outside these exact routes. HEAD must not start a producer. HTTP/1.1 remains byte-compatible. No broader API, page, capability, inventory, MCP, existing sitemap CSV, import/export or known-length original-body download is rejected by this new guard.

This change is deliberate and needs the narrow source review: unknown-length close-delimited HTTP/1.0 cannot reliably tell an early transport close from a complete response. HTTP/1.1 chunk framing and an explicit Body error can expose truncation. Future original-body downloads already prepare an exact-length private spool; their HTTP/1.0 behavior is therefore not automatically refused. This scope decision does not claim that all other legacy HTTP/1.0 streams have acquired an independent truncation guarantee.

## Concrete accept and connection ownership seam

Add a separate server/transport.rs module and its source-only tests in a later authorized slice. Keep all existing Router construction, state, middleware, limits, local-origin checks, bind-address resolution, recovery, print/ready sequencing and MCP local-address registration. Replace only the final axum::serve orchestration with a transport owner. AppState/Lifecycle must hold the transport registry strongly until actual drain, rather than relying on a temporary waiter.

The transport registry owns two retained TaskOwners (accept coordinator and connections) and a sticky shutdown phase. Register the accept coordinator and actual listener before announcing ready. Use the same shared admission gate for connection registration as other local owners. An accepted socket is registered under that gate before its work start barrier is released. If shutdown wins the race, registration fails and the owned socket is dropped without admitting a handler. The accept loop checks the sticky phase before and after select/accept; a closed gate is the authoritative race guard. Reuse Axum's public Listener::accept behavior to preserve logging, retry and its one-second backoff for non-connection accept errors; do not replace it with a tight failing loop.

The accept coordinator retains/polls actual connection tickets (or another explicit completion notification) and reaps completed TaskOwner slots during ordinary service. The reaper runs even if no later connection is accepted. It must not depend only on the next incoming client, and must not create a detached timer/reaper. Actual worker and supervisor JoinHandles remain in TaskOwner until join, so cancellation of a completion/drain waiter cannot detach them. The coordinator returns after closing its actual listener at quiesce; existing connection joins and grace enforcement remain separately owned. Join both coordinator and connection owners in final drain.

Each connection task lexically owns its TcpStream wrapped in TokioIo, a cloned finalized Router adapted by TowerToHyperService, and `auto::Builder::new(TokioExecutor::new()).serve_connection_with_upgrades(...)`. Router<()> already implements Tower Service<Request<B>> for compatible incoming bodies and maps them to Axum Body; the adapter drives readiness. This preserves the same parser/builder/default configuration used by locked Axum instead of constructing a different HTTP stack. Do not use http1_only as a substitute for feature admission: cached code notes that option does not affect serve_connection_with_upgrades. Absence of http2 in the actual feature graph is the intended boundary.

Keep a private per-connection cancellation/control token in Request extensions via a narrow adapter around the finalized Router. It identifies actual transport terminal/drop without changing a public request DTO. Later policy/resource and BODY response owners can bind their Pending/Body lease to it. This matters before headers: the generic RequestOwner deliberately retains the handler even after the connection's caller future is dropped, so that retained handler alone does not observe client disconnect. Publishing connection terminal must wake an associated preparing/unattached response owner as well as an already streaming Body. Direct handler/unit tests without a transport token still use their explicit test cancellation/drop control.

On quiesce, each live connection invokes graceful_shutdown exactly once on its pinned connection future and keeps polling it. On forced transport abort, leave the lexical scope which owns the real connection future/IO so they are actually dropped, then let the enclosing owned task return a typed ShutdownAborted outcome and be joined normally. Calling drop on only a Pin<&mut Future> is not sufficient; the underlying future/stream must leave scope. Do not abort/discard the task JoinHandle. An RAII connection-terminal guard publishes terminal even on panic, while TaskOwner records the actual failed join. No outbound Reqwest/website socket or other process is closed by this code.

Classify expected peer disconnect/protocol errors separately from owner failures. Existing Axum traced ordinary serve errors; an attacker sending malformed HTTP must not automatically poison every later shutdown. Keep explicit terminal counters/outcomes (completed, peer/serve error, shutdown aborted), whereas worker/supervisor panic, missing handles, incomplete join accounting or resource cleanup failures remain sticky ownership failures. A connection outcome does not convert a cancelled download into SUCCESS_EOF. Record the respective response registry outcome independently.

## Five-second grace and concurrent drain

At the actual local shutdown signal time T0, synchronously close the shared application, response and transport admission, publish QUIESCING with one monotonic `abort_at=T0+5s`, stop accept/listener activity, and preserve active-crawl pause/cancel behavior. Existing newly designed policy/resource/BODY producers may complete during the grace period; close their admission at T0 but do not force all of them to fail immediately merely by starting their drain. Peer/Body Drop still cancels an individual response immediately. Preserve existing sitemap CSV/read/FileTools shutdown semantics rather than silently changing them to this new grace policy.

Drive the transport grace coordinator concurrently with all retained request, producer, response, crawl, CSV/read/file and stdin-monitor joins. It races actual connection completion with sleep_until(abort_at). If all inbound transports already ended, no artificial five-second delay is required. Otherwise at the shared deadline it synchronously requests abort on nonterminal response controls and publishes ABORT to remaining owned connections. Then keep awaiting actual connection, Body, producer, supervisor, spool and permit closure; do not return merely because the timer fired. The grace future itself is retained by the serve/lifecycle coordinator and creates no detached sleep task. A failed signal source follows the same cleanup before returning its error.

Use one absolute deadline for the group rather than giving each sequentially joined connection another five seconds. The source-level design introduces no hard real-time guarantee: a blocked Tokio runtime, an uninterruptible verified operation or an outbound crawl can delay actual completion. Closing an inbound socket does not stop or abandon those owners. In particular do not wrap the full drain in timeout and drop all futures to manufacture a five-second PASS. An intentionally aborted transport may contribute to a clean ownership receipt only when actual joins/closes succeed; its response remains ABORTED. Natural process/stdout/stderr closure stays an independent native witness.

## Narrow required checks before implementation admission

- Actual locked feature evidence after adding only hyper-util direct use: no new h2, HTTP2/WS/HTTP3 feature or package; preserve every actual current feature. Test h2 prior-knowledge bytes remain refused/errored instead of inventing support.
- Before/after real requests for HTTP1.0 and1.1 health/index/MCP/inventory/ordinary exports, GET/HEAD behavior, host/origin rejection, unknown route and wrong methods. HTTP1.0 refusal is only the four explicit streaming MethodRouters and starts zero workers/SQLite work. HTTP1.1 positive export bytes/tails remain exact.
- Actual upgrade headers and CONNECT against the existing paths, unknown paths and authority form retain the current unsupported behavior and create no upgraded worker/IO. No test assumes a single unverified status for every parser form.
- Admission-close racing socket acceptance/start; zero late handler starts; coordinator listener actually dropped; completed connection slots reaped while otherwise idle; dropped completion/drain waiter retains actual handles.
- Deterministic paused-time tests prove grace does not abort an active inbound connection before the single T0+5s deadline, a consuming response finishing in grace completes naturally, and the remaining Pending AsyncWrite connection is actually dropped and joined after the deadline without needing Body polling. Preserve a network/native follow-up; clock tests alone are not wire proof.
- A live outbound held website response and verified blocking worker remain owned after the inbound deadline. The process cannot claim full drain until their real completion; checkpoint/pause/cancel assertions remain unchanged.
- Actual TCP non-reader with real queue/write backpressure markers, explicit truncated/error client outcome and natural final process/pipe closure. No releasing the non-reader before asserting autonomous abort, no PASS kill, no borrowed Source5 result.

This document authorizes no implementation itself. First obtain the actual final Source5 R2 source admission, then separately authorize response owner/writer/Body tests and the accept/connection integration.
