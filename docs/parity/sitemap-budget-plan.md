## Feasibility: CSV64MiB is reachable without a forged catalog

A universal2x CSV/catalog bound is false. For an original raw quote:
- Raw value JSON uses two bytes, backslash plus quote.
- In CSV typed_row_json the same two-byte JSON sequence becomes three bytes because the CSV writer doubles its literal quote.
- The separate CSV raw_value column contributes two bytes.
Thus a quote contributes five CSV bytes against two catalog row JSON bytes.

Smallest proposed genuine path: about110 fresh original sitemap URLs of the form http://<owned-origin>/empty.xml#<about122000 literal quote characters>. All normalize to the same short actual protocol URL, while original fragments remain in fresh explicit input capture. Each root stays around244KiB encoded, below the default256KiB row cap. Total original provenance/catalog is around27MiB while CSV reaches64MiB. The actual short /empty.xml route returns complete <urlset/> and is fetched once; root admission records Scheduled plus real coalesced duplicate declarations. Seed and fixtures are owned. Do not manually supply contradictory explicit_sitemap_inputs.

Static source supports this path: pinned normalize_url calls URL::parse then set_fragment(None); locked url2.5.8 primary installed parser declares quotes in its FRAGMENT percent-encoding set and encodes fragment parts without treating quotes as parse failure. First implementation gate must nevertheless be a small actual Rust constructor/normalizer control proving that a quoted fragment is preserved as original, normalizes to the short task, and is actually admitted/coalesced. No full native quote fixture has been executed by this author.

Fallback: genuine /api/lists/import sitemapindex XML files can retain rejected quote-only Loc values as SitemapDocument importer rows. Use actual returned importer results, not authored import JSON. Four roughly3.3MiB raw inputs with <=8192-byte fields fit each importer8MiB serialized result and the combined32MiB provenance limit; about1700 imported roots also provide the5/2 amplification. This is valid but less compact and potentially slower than110 actual explicit fragment roots. Quote-only values in fresh sitemap_urls are rejected and must never be used as the positive route.

ASCII nonquote characters contribute two CSV bytes (one in typed JSON plus one in raw column) and one catalog byte. Quote/ASCII increments5 and2 allow exact CSV length tuning while remaining nonformula text. Root IDs/config hashes change but retain fixed64-byte hex lengths. Measure actual native output; a predicted arithmetic length is not an acceptance result.

## A native default1,000,000-row boundary is unreachable first

Every validated typed row includes at least one exact64-character digest ID in a JSON string, so its serialized size is at least66 bytes even before keys/tags/other fields. A million rows therefore needs at least66,000,000 bytes, already above the32MiB full catalog cap. The conservative catalog-only upper bound is floor(33,554,432/66)=508,400 rows before envelope/comma overhead, substantially below1,000,000. Thus a positive native million-row fixture at default32MiB cannot be built; test configurable lower row caps through the actual existing Core/Store API and label them integration budget controls. Catalog/row native physical boundaries above are reachable. The native row-count product setting remains absent.
