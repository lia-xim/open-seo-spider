## Smallest coherent implementation stage

1. Add only an explicit Serve flag, provisionally `--shutdown-on-stdin-eof` (default false), and an internal serve entry point that accepts an injected shutdown future for tests. Preserve existing entry points and defaults. The flag is for an owner that spawns this exact child with a retained stdin pipe and keeps it open. Read and discard bounded chunks until actual EOF; do not accumulate arbitrary stdin or interpret it as protocol. No extra network admin route, remote token, MCP tool or tool argument.

2. Use one application lifecycle owner with monotonic Running -> Quiescing -> Joining -> Closed/Failed. At shutdown initiation, atomically close admission before asking Axum to stop accepting. Closing admission and registration of request tasks, crawl launch tasks and ordinary blocking tasks must use retained shared slots under the same admission lock; a boolean checked before an await is insufficient. Register before spawn/start, release the lock before awaits. New work after quiescing returns a bounded existing-style shutdown error and starts no task or file reservation. Existing operation types and validation remain intact.

3. Move expensive draining OUT of Axum's graceful-signal future. That future resolves promptly after the admission transition. Run Axum connection completion and retained application drains concurrently under the owner; consume every result before returning. Stopping acceptance can make an already admitted MCP bridge's subsequent self-HTTP call fail. Preserve a bounded transport/tool error instead of asserting that every accepted request necessarily succeeds. Never await all admitted bridge calls before signaling or canceling the registry work they are waiting on. Do not leave a temporary internal bypass header, loopback admin exemption or a listener accepting fresh work just to support self-HTTP.

4. Track complete request/supervisor handles through their actual close, and every ordinary request-bound blocking handle through its actual join even if the HTTP caller disconnects. Reuse the FileTools shared-slot/supervisor ownership pattern rather than detaching on Drop or using JoinHandle::is_finished as a join substitute. Existing CSV/read registries retain their own controls and bodies. If request result receivers vanish, workers still finish or cooperatively cancel under their existing rule. CPU serializers without cooperative cancellation are joined, not falsely declared interrupted. Inline synchronous handlers can still block an executor; no hard wall-clock drain guarantee follows from retaining handles.

5. Track each whole crawl launch from its pre-IO admitted mutation operation through the event task, Core return, checkpoint, report/revision and final job manifest. Request_pause on all active crawl controls when quiescing; join whole launch handles before success. Keep cancellation result semantics unchanged. Add independent ownership for Core PDF blocking analysis so an already requested or concurrent Cancel cannot detach it when Page futures drop. A failed terminal write, task panic, missing join or accounting mismatch prevents success. Do not acknowledge shutdown merely from job.status becoming terminal. Selected child reservation/initialization failures must run their existing owned cleanup before the admitted operation is joined.

6. Join FileTools, findings reads, CSV exports, request supervisors, ordinary blocking workers and crawl launches. Keep registry failures sticky and final drain idempotent/recoverable if a waiter is canceled. A single coordinator owns the real shutdown; observing/canceling a waiter must not cancel the coordinator or remove its handles. A deadline reports pending/failed drain and retains evidence; it must never convert a timed-out join or forced kill to graceful success.

7. In the opt-in stdin mode, actual EOF is the primary owner signal and its read monitor must finish and be joined. A Ctrl-C can request quiescence, but success must still await EOF/monitor completion; the documented owner must close the pipe on every exit path. An interactive/open stdin with Ctrl-C is outside the new EOF guarantee. Do not hide an unjoined Tokio blocking read in a select branch or claim that abort() stopped it. The default Serve Ctrl-C path must not start any stdin read.

8. Produce an optional structured local stderr lifecycle receipt only after all owned joins. Include cause, source/build identities supplied by acceptance binding, monotonic clocks, admitted/rejected/started/joined/failed/retained counts per owner, Axum result, paused checkpoint/report generations and stdin-monitor completion. Keep native process close + pipe drain as an independent outside witness. Do not publish these implementation counters in ordinary product flows or add a public HTTP diagnostics/admin endpoint solely for this test.

The proposed new ownership surface should be small and explicit (for example a `server/lifecycle.rs` owner used by Serve, the relevant handler worker wrappers, and Core's PDF join guard). Do not alter FileTools descriptors/permissions or rewrite the three working registries. Re-evaluate exact file ownership only in a future source proposal, not by editing Source V4.

SIGTERM/SIGKILL fallback, missing process/pipe close, still-live worker, unresolved joins, panic, partial serialization claimed complete, missing overlap or state mismatch means FAIL/NOT PROVEN.
