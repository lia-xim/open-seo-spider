# Main result table: filters and column views

This is the independent `ui.filter` implementation contract. The [bounded local native acceptance](verification/table-explorer-20261018-r4/README.md) passed six native groups, 36 views and five complete CSV files with 521 data rows. A same-origin cold reopen and all 42 registered UI suites passed in one fresh R4 invocation. Four explicit Rust/Chromium fixtures passed separately on R4. The R3 workspace result of 1,831 passed, zero failed and five ignored tests, format and strict Clippy are explicitly reused because only six test files changed. They were not rerun as a new R4 workspace gate. This does not establish manufacturer parity or change the full feature inventory.

Open **Ansicht und Filter** above a main result table. Add text contains/equals rules or inclusive numeric minimum, maximum and range rules. Every accepted rule, the existing section filter and the global search are combined with AND. Global search uses the entire section schema, including hidden columns. Text is trimmed, normalized to NFC and compared without case in the German locale; accents remain distinct. Decimal input uses a point and rejects empty, nonfinite or malformed bounds. Invalid rules keep the accepted selection and show an error; CSV is disabled until the rule error is cleared or corrected.

**Wert vorhanden**, **Kein Messwert** and **Leerer Text** distinguish measured zero/false, missing or unsupported measurements, and captured empty text. Numeric comparisons never convert unknown values or empty text to zero. Numeric measurements and explicitly mapped raw text drive their rules and sorting, preserving missing and observed-empty states. Translated categorical columns use their declared scalar mapping; this does not promise that every categorical rule reads a raw boolean. Display labels remain available to global search, including hidden columns. Derived unobserved browser selection and unexecuted schema validation are unknown values. Absence of a title tag is distinct from an observed empty title tag.

Sorting applies to all selected rows before the existing 50-row pagination. Known values precede empty text and then unknown values in both directions. Primary sort ties are resolved by ascending complete source identity (requested and observed URLs, occurrence coordinates, rule and source); only exact identity ties fall back to occurrence ordinal/input index, independently of the primary direction. Rows are not deduplicated by URL. The original row still opens its own inspector. Changing a project or section clears temporary search/rules and resets sorting; changes in a live generation retain the current section's filters.

Select and reorder columns with the checkbox and arrow controls. Required identity columns stay visible at the beginning: the URL for ordinary result tables, the list/hash/source coordinates for imported occurrences, and observed URL/requested URL/response position for response occurrences. The current section's CSV contains every filtered row, including pages outside the visible page, in the selected column order, followed by the existing provenance fields. Overview and graph exports retain their separate export scope. Dedicated policy, content, resource and sitemap inventories keep their own controls and pagination.

**Spalten speichern** explicitly stores one column-key projection per saved crawl ID and section in this browser origin's local storage. It saves no results, credentials, filters or sort order. Reopening the same crawl and section loads only a valid stored projection. Browser, origin or port changes do not transfer it automatically. There are no multiple named presets or portable preference import/export in this slice. **Spalten zurücksetzen** removes only the selected crawl/section preference and restores default columns while preserving accepted filters. Invalid stored bytes and storage failures remain visible and are not silently overwritten; clearing or saving is explicit. Another tab's storage change does not replace the current view automatically.

The helper bounds configuration to 128 columns, 16 combined rules, 4,096 UTF-8 bytes per search/rule text and 65,536 stored preference bytes. These are configuration limits, not a URL cap. It filters all rows already loaded by the main dashboard; large-dataset memory and interactive latency limits require separate measurement.

Acceptance requires genuine native captures with more than 100 observations; independent all-row and complete CSV checks; zero, empty and unknown controls; Unicode normalization; both sort directions; duplicate response identities and inspectors; explicit save/reset and project/section isolation; a fresh browser after a natural native shutdown; unchanged saved report bytes; no offline product refetch; invalid preferences/storage failures; and usable controls at 320 px and desktop width. Browser-only fixtures or helper tests alone do not satisfy this contract.
